CIM data models

A data model is a vendor-agnostic schema plus a membership rule that decides which events belong to it. Membership is evaluated in Python at ingest and stored in events.cim_models, so a detection binds to datamodels: web instead of listing every vendor that speaks HTTP — onboarding a new source becomes a registry edit in app/cim/models.yaml, not a code change. Querying a model

Every model is addressable three ways — by display name or by tag, case-insensitively. Inside a model the vocabulary is the model's own field names (below), not the events columns they come from.

WhereSyntaxWhat it does
LOQLfrom datamodel:Authentication action=failure | stats count by user Search the model instead of a vendor. | datamodel Authentication is the same query.
Sigma ruledatamodels: web Bind a rule to the model. Narrows with logsource:; several models mean any of them.
SQLSELECT * FROM cim_authentication One view per model, rebuilt from the registry on every startup.
